# LifeCycle

Reusable lifecycle-consumption and portfolio optimization workspace.

## Structure

| Folder | Purpose |
|---|---|
| `model/` | Core MATLAB/Octave lifecycle model source (`life_cycle.m`, helper `f_*.m`). |
| `data/` | Saved policy/value output snapshots such as `yearXX.txt`, `CWY.txt`, `CWYs.txt`, and `SB.txt`. |
| `outputs/` | Experiment outputs generated by runner jobs, reports, CSVs, figures, and scenario artifacts. |
| `skills/lifecycle-optimizer/` | Codex skill layer: instructions, configs, scripts, tests, review helpers, and agent prompts. |
| `skills/lifecycle-optimizer/agents/` | Reusable validator, runner-tester, and critic prompts for subagent review. |
| `app/` | Project-level entrypoints for running the optimizer as a system. |

## Product Modules

| Module | Purpose |
|---|---|
| `app/client_input.py` | Parses natural-language client text into age, wealth, risk preference, and `rho`. |
| `app/policy_guardrails.py` | Applies product risk controls, rejects unsafe model outputs, and derives safer customer allocations. |
| `app/risk_metrics.py` | Estimates max drawdown, failure probability, volatility, and terminal wealth through Monte Carlo. |
| `app/advisor.py` | Combines parsed input, completed model artifacts, policy interpolation, risk metrics, and customer explanation. |
| `app/batch_compare.py` | Generates random clients and compares lifecycle policy against naive 60/40. |
| `skills/lifecycle-optimizer/scripts/policy_explainer.py` | Rule-based customer-facing explanation layer. |
| `app/run_agent.py` | CLI demo for customer-manager usage. |
| `app/app.py` | Streamlit demo UI. |

## Quick Commands

Dry run:

```powershell
py app/cli.py --dry-run --max-evals 2
```

Real model smoke test:

```powershell
py app/cli.py --real --fast-mode --max-evals 1 --timeout-sec 1200
```

Customer-manager demo:

```powershell
py app/run_agent.py "45 years old, 1 million, stable returns"
```

Batch comparison against naive 60/40:

```powershell
py app/batch_compare.py --clients 100 --paths 1000
```

Streamlit demo:

```powershell
streamlit run app/app.py
```

Unit tests:

```powershell
py -m unittest discover -s skills/lifecycle-optimizer/scripts -p test_*.py -v
py -m unittest discover -s app -p test_*.py -v
```

## Model Notes

The business objective is lifecycle utility / value function, not terminal wealth.
`rho` means the agent's risk aversion or risk preference parameter: higher `rho` means more risk averse.

Use `na=20`, `ncash=20` for meaningful diagnostic validation. Keep `10x10` only for smoke tests, and use `40x40` only for slower robustness checks.
